# Application audit — orphaned, disconnected & partial implementations

Date: 2026-11-13 · Scope: `apps/web` (Angular) + `apps/api` (Slim/Doctrine) · Method: four parallel read-only sweeps (frontend orphans, backend wiring, frontend↔backend contract, partial implementations), with every P0/P1 claim spot-checked against the code. ✔ = verified by hand.

**Headline:** structurally the codebase is tidy — every backend route resolves to a real method, every Action is routed, and the migrations match the entities column-for-column. The problems are (1) missing authorization on several endpoints, (2) features that work only on **seeded** data and break for real schools, (3) settings and form fields that are saved but never read, and (4) a dozen orphaned components.

### Deliberately left (with reasons)

- **Naming convention, class structure, localisation, data preferences** (school settings): kept and labelled "kept on record"; applying them touches every screen that formats a name or date. Needs a product decision on scope.
- **Per-school theming:** the brand colour is shown as an accent in the top bar, not applied as a full theme (the product's house style is the green theme).
- **Daily/weekly study reminders, SMS, push:** toggles removed rather than faked; no sender exists.
- **Pricing page / contact form:** "Contact us" pricing and the `mailto:` contact form are intentional and clearly labelled.
- **Dead columns** (`Institution.subscription_id`, `LiveClass.room_url`, `TeacherAssignment.status`, `Report.status/params`, …): not dropped. Dropping columns is irreversible on production data and brings no behaviour change.
- **Dead endpoints:** left in place (several are now used, e.g. `GET /auth/user-profile/{id}`); all are covered by the permission matrix.
- **`ramsey/uuid` / `autoload-dev`:** unchanged, to keep the deploy a plain `git pull` + migrate (no `composer install`).
- **Safeguarding reports** are still blocked (402) for schools whose plan lacks the safeguarding module. Flagged for a product decision: reporting a concern arguably should never be plan-gated.
- **Content library** (`GET /content/library`) lists the platform catalogue to any signed-in user with resource access; treated as intended.

## P2 — Saved but never used (write-only settings & data)

- **Super-admin System Settings are entirely inert** — `PlatformSetting` is referenced only by its own action: maintenance mode, self-signup, email verification, feature flags (incl. unimplemented `ai_grading`), password min length (hard-coded 8), session timeout, enforce 2FA, rbac_enforce, integration switches. ✔ `SystemSettingsAction.php:22-56`
- **School settings:** academic, localization, branding, notifications, data sections and `grading.pass_mark` never read; `grading.weighting` *is* read by the gradebook but nothing can set it, so blended grades can't be enabled. `school-settings.ts:118` hard-codes "Notification Defaults" as done. `SchoolSettingsAction.php:34-67`
- **User preferences inert:** the 2FA toggle shows "Enabled" but login never checks it; email-alert preference ignored (`NotificationService` always emails). `UserSettingsAction.php:72-137`
- **Onboarding data write-only:** guardian contacts, medical/special-needs notes, consents, admission date, previous school, staff ID/department/qualification are saved to `User.onboarding` and never read. The teacher's displayed Staff ID is **fabricated** (`LRN-TE-0005`). `OnboardingAction.php:63-75,108-118`; `UserSettingsAction.php:60`
- **Branding:** brand colour stored under two keys (`branding.color` vs `branding.primary_color`), never applied as a theme; the settings field reads a key the API never returns (always shows default). `SchoolProfileAction.php:72-80`, `UpdateInstitutionAction.php:49-52`, `school-settings.ts:117`
- **Topic fields never written** (`prerequisites`, `misconceptions`, `question_types`, `workplace_relevance`) yet displayed by Insights, Analytics, Dashboard and the approval queue — always empty. `strand`/`core_theory` accepted by the API but no form sends them. `Topic.php:54-71`
- **Misconception data not used:** `misconception_tag` + `common_wrong_answer` (captured by the bulk import) aren't used by Insights or feedback-suggest yet.
- **Two "class teacher" sources:** `TeacherAssignment` (teacher classes, tutor inbox, dashboard, submissions) vs `SchoolClass.classTeacher` (teacher-students, classes & learners). A `TeacherAssignment` can only be created at staff onboarding — no UI edits or removes one.
- **Scheme of Work form:** Status dropdown, and class/subject on update, are ignored. `scheme-form.ts:82`; `SchemeOfWorkAction.php:213-243,304-316`
- **Question picker capped at 100** (UI asks for 200; `ListQuery` caps 100). `assessments.ts:119`
- **Institution type mismatch:** onboarding stores `tutoring_academy`, super-admin KPI/filter counts `academy` → academies show 0. `InstitutionFields.php:18`; `super-admin/institutions.ts:61,71`
- **Institution packages:** multi-select, but only the first is stored; clearing doesn't unassign. `InstitutionFields.php:41-55`
- **School profile save wipes** the admin contact's first/last name. `SchoolProfileAction.php:82-88`
- **Content-package price/duration/type** stored but never charged, enforced or expired.
- **Report-card "Attendance"** is actually live-class join rate (no school attendance data).
- **Resource viewer "done" + notes** live in localStorage only (lost across devices, invisible to teachers) although a server-side `StudentTopicNote` exists. Onboarding "Save draft" stores the full form — incl. temporary password and medical notes — in localStorage.
- **Feedback focus areas (from the earlier NOTE work):** untouched bars default to 70%, and auto-fill copies one overall accuracy into all four areas (incl. "Showing Working"). The teacher can override, but learners can receive scores nobody set. `feedback-compose.ts:53-58,107-108`
- **Portfolio (from item 10):** with the sheet builder hidden, `submitTask` still saves the hidden *default* mission/rubric labels into `topic.portfolio_task`. `portfolio.ts:43,152-154`
- **Storage:** `StorageService::delete()` is never called → deleting a resource leaves the file on disk; `STORAGE_DRIVER` / `STORAGE_PUBLIC_URL` / `PAYSTACK_PUBLIC_KEY` read but unused; `PasswordService::needsRehash()` never called; ModuleGate doesn't cover `/assessment/submissions/*` and `/assessment/insights`; `SchoolClass.status` (inactive) is not honoured anywhere.
- **Smaller:** contact form is `mailto:` only; pricing page hard-coded (not from DB plans); footer year hard-coded 2026; new-student/new-teacher always show "Your school"; email failures silent when ZeptoMail token is missing.
